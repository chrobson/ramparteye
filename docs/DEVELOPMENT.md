# Development

## Requirements

- Go (the version in [go.mod](../go.mod));
- Docker with Compose 2.24 or later for integration tests, the image and the lab;
- nothing else: no Node.js. The Tailwind standalone CLI is downloaded on demand.

## Build and run

```sh
make build                 # bin/ramparteye (VERSION=dev)
make image                 # container image ramparteye:dev
RAMPART_INSTALL_LOCAL_IMAGE=ramparteye:dev ./install.sh --demo --dir /tmp/ramparteye-demo
```

`go build ./...` works on a fresh checkout: the generated CSS, templates, static files and
built-in signatures are embedded with `go:embed`.

To run the binary outside Docker you need PostgreSQL (with `pg_tde` for encryption at rest) and
nmap on the `PATH`:

```sh
make test-db               # throwaway Percona PostgreSQL + pg_tde on 127.0.0.1:55432
export RAMPART_DATABASE_URL='postgres://rampart:rampart@localhost:55432/rampart?sslmode=disable'
export RAMPART_SECRETS_DIR=$PWD/tmp/secrets RAMPART_ALLOWED_CIDRS=127.0.0.1/32
bin/ramparteye serve       # http://localhost:9080, admin password printed once
```

## Tests

```sh
make test                  # go vet + go test -race ./...
make test-integration      # starts the test database (tools/test-db.sh), then -tags integration
make e2e                   # demo stack + lab: three scans, precision/recall 1.0 (scripts/e2e.sh)
make shellcheck            # install.sh, scripts, lab and tools
```

- Tests use [ctx42/testing](https://github.com/ctx42/testing) (`pkg/assert`, `pkg/must`,
  `pkg/mock`) only.
- Unit tests never touch the network or execute nmap; scanners, HTTP and stores are faked.
- Tests that need PostgreSQL carry the build tag `integration` and run against the
  Percona `pg_tde` image started by [tools/test-db.sh](../tools/test-db.sh); each test gets its own
  schema. `make test-integration` needs Docker (`make test-db-down` removes the container).
- `make e2e` builds the image, starts the demo stack, scans the lab three times with
  `lab/change.sh run2` and `run3` in between, and checks every run with `ramparteye verify`
  (hosts, services, detections and changes against [lab/expected](../lab/expected)) and
  `ramparteye audit`. It needs about 2 GiB RAM and the lab subnet `10.20.0.0/18` free. See
  [lab/README.md](../lab/README.md).
- New behaviour is written test-first: a failing test, then the code.

## CSS

The UI uses Tailwind CSS 3 built with the standalone CLI, pinned with SHA-256 checksums per
platform in [tools/tailwind.sh](../tools/tailwind.sh). The generated
[web/static/app.css](../web/static/app.css) is committed.

```sh
make css                   # rebuild app.css after changing templates or web/tailwind.input.css
make css-check             # CI: fails when the committed app.css is stale
```

## Vendored JavaScript

[htmx](https://htmx.org) 2.0.4 and the htmx SSE extension 2.2.2 are vendored unmodified in
`web/static`; versions, source files and SHA-256 sums are listed in
[web/static/htmx.LICENSE](../web/static/htmx.LICENSE). When updating, replace the files, update
the sums and check the UI (`make e2e` covers the main pages). `web/static/app.js` holds the few
lines of our own JavaScript (theme toggle, confirm dialog, tabs).

## Lab

The demo lab is inlined in [compose.demo.yml](../compose.demo.yml); [lab/](../lab) holds the
variants, `change.sh` and the ground truth generated by `lab/gen_expected.py`
(`python3 lab/gen_expected.py --check` in CI). Edit the generator, never the JSON.

## CI

[.github/workflows](../.github/workflows):

- `ci.yml`: `go vet`, unit tests, `make css-check`, shellcheck; integration tests against the
  `pg_tde` test database.
- `e2e.yml`: lab ground truth freshness and `make e2e`.
- `release.yml`: on a `v*` tag, multi-arch GHCR image and binaries. Nothing has been tagged yet.

Base images and actions are pinned to version tags; pinning to digests at release time is on
the [roadmap](../ROADMAP.md).

## Repository layout

```
cmd/ramparteye/   subcommands and wiring
internal/         packages (see docs/ARCHITECTURE.md)
web/              templates, static files, Tailwind sources
deploy/           database init SQL and deployment tests
lab/              lab variants, change.sh, ground truth
scripts/          e2e.sh
tools/            tailwind.sh, test-db.sh
docs/             documentation, logo, screenshots
```

## Conventions

- English everywhere: code, comments, UI copy, logs, docs.
- Commit messages: `type(scope): short lowercase imperative subject`, at most 60 characters
  (`feat(runner): ...`, `fix(web): ...`, `docs: ...`).
- Keep the safety model intact: nothing that sends a request body or a method other than
  `GET`/`HEAD`, nothing that scans outside the scope. See [SECURITY-MODEL.md](SECURITY-MODEL.md).
