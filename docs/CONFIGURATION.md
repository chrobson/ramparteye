# Configuration

RampartEye reads its configuration from `RAMPART_*` environment variables. With the installer
they live in `.env` next to `compose.yml`; apply a change with `docker compose up -d`. Settings
edited in the UI (scan profiles, targets, signatures, users, the DefectDojo connection) are stored
in the database.

## Installer

```sh
curl -fsSL https://raw.githubusercontent.com/chrobson/ramparteye/main/install.sh | sh -s -- [options]
# or from a checkout:
./install.sh [options]
```

| Option | Meaning |
|---|---|
| `--scope CIDRS` | Networks RampartEye may scan, comma separated (`192.168.1.0/24,10.0.5.7`). Asked for interactively when missing. |
| `--demo` | Start the bundled scan lab and the four demo accounts instead of a real scope. Excludes `--scope`. |
| `--dir DIR` | Install directory (default `./ramparteye`). |

| Installer variable | Meaning |
|---|---|
| `RAMPART_PORT` | UI port on the host (default 9080). Ports below 1024 are not supported: the container drops all capabilities. |
| `RAMPART_DB_PORT` | Database port on the host loopback (default 55432). |
| `RAMPART_INSTALL_LOCAL_IMAGE` | Use a locally built image (for example `ramparteye:dev` from `make image`) instead of `ghcr.io/chrobson/ramparteye:latest`. |
| `RAMPART_INSTALL_SOURCE` | Copy the compose files from this directory instead of downloading them (a checkout running `./install.sh` does this itself). |

The installer checks for Docker and Compose 2.24 or later, writes `.env` (mode 0600) with a
random database password, starts the stack and waits until the app is healthy. Running it again
keeps the existing `.env` and only updates `RAMPART_ALLOWED_CIDRS` when `--scope` is given. A
directory holds either a demo or a regular install, never both.

Files and volumes:

| | Content |
|---|---|
| `.env` | Settings and the database password. |
| `compose.yml` | App and PostgreSQL (pg_tde). On Linux the app uses host networking so nmap reaches the LAN. |
| `compose.demo.yml` | Demo only: the lab network with about 30 targets; the app joins it instead of the host network. |
| volume `pgdata` | The database. |
| volume `pgkeys` | The pg_tde keyring. |
| volume `secrets` | The app's AES-GCM key `secret.key`. |

Back up `pgkeys` and `secrets` together with `pgdata`; see
[SECURITY-MODEL.md](SECURITY-MODEL.md#7-data-at-rest-and-keys).

## Compose variables

These are read by `compose.yml` itself.

| Variable | Default | Meaning |
|---|---|---|
| `RAMPART_IMAGE` | `ghcr.io/chrobson/ramparteye:latest` | App image. |
| `RAMPART_DB_PASSWORD` | (required) | Database password, generated by the installer. |
| `RAMPART_BIND` | `127.0.0.1` | Address the UI listens on. `0.0.0.0` exposes it to the network; put TLS in front of it. |
| `RAMPART_PORT` | `9080` | UI port. |
| `RAMPART_DB_PORT` | `55432` | Database port on the host loopback. |
| `RAMPART_TZ` | `UTC` | Time zone of scan windows and UI times. |

## Application variables

### Scope

| Variable | Default | Meaning |
|---|---|---|
| `RAMPART_ALLOWED_CIDRS` | (empty) | Networks that may be scanned: CIDRs or single addresses, IPv4 or IPv6, comma separated. **Empty refuses every scan and target import.** |
| `RAMPART_ALLOW_HOSTS` | (empty) | Host names allowed in addition; resolved at start, each address becomes part of the scope. A name that does not resolve stops the start. |
| `RAMPART_SCAN_EXCLUDE` | (empty) | Addresses never scanned, even inside the scope. |
| `RAMPART_SCAN_PORTS` | (empty = any) | Allowed TCP ports, e.g. `22,80,443,8000-8100`. |

### Scanning

| Variable | Default | Meaning |
|---|---|---|
| `RAMPART_MAX_RATE` | `5000` | Packets/s upper bound of every run; profiles may only set less. |
| `RAMPART_SCAN_PRIVILEGED` | `false` | SYN scan (`-sS`) instead of connect scan (`-sT`). Needs, as in `compose.demo.yml`: `cap_add: [NET_RAW, NET_ADMIN]`, no `no-new-privileges` (`security_opt: !reset []`, otherwise the nmap copy's file capabilities are ignored), `RAMPART_NMAP_PATH=/usr/local/bin/nmap-privileged` and `NMAP_PRIVILEGED=1`. |
| `RAMPART_NMAP_PATH` | `nmap` | nmap binary. |
| `RAMPART_ALL_PORTS_MAX_ADDRS` | `16` | The `auto` port profile scans all 65535 ports for chunks of at most this many addresses (0 disables); otherwise the top 1000 ports plus a pass over common infrastructure ports. |
| `RAMPART_TICK_EVERY` | `1m` | Scheduler tick: how often scheduled profiles and paused runs are checked. |

Scan profiles (Configure → Scan profiles) set the targets, port profile (`auto`, `top`, `list`,
`all`), packets/s, worker count, an optional time window and schedule. A run is split into /24
chunks; each chunk is tried up to 3 times. Runs started with "Run now" ignore the window. A run
stopped by a shutdown or by the end of its window resumes on a later scheduler tick, as long as
its profile is enabled.

### HTTP fingerprinting and signatures

| Variable | Default | Meaning |
|---|---|---|
| `RAMPART_HTTP_TIMEOUT` | `10s` | Per-request timeout. |
| `RAMPART_HTTP_RETRIES` | `1` | Retries per request, 0-3. |
| `RAMPART_PATH_PROBES_PER_HOST` | `50` | Signature path probes per host per run; `0` disables path probes. |

HTTP probes run at 20 requests/s with a burst of 5 and only send `GET`/`HEAD`.

### Host states

| Variable | Default | Meaning |
|---|---|---|
| `RAMPART_INACTIVE_AFTER_MISSES` | `3` | A host becomes inactive after this many runs without seeing it. |
| `RAMPART_UNSTABLE_IF_FLIPS` | `2` | A host is unstable after this many up/down flips... |
| `RAMPART_UNSTABLE_WINDOW` | `5` | ...within this many recent runs (at least `RAMPART_UNSTABLE_IF_FLIPS`). |

A latency change is reported when the response time changes by more than 300 ms between runs
and at least doubles or halves; a host keeps the history of its
last 30 runs in the drilldown.

### Server

| Variable | Default | Meaning |
|---|---|---|
| `RAMPART_DATABASE_URL` | set by compose | PostgreSQL connection string. |
| `RAMPART_HTTP_ADDR` | `:9080` (compose: `RAMPART_BIND:RAMPART_PORT`) | Listen address. |
| `RAMPART_TRUSTED_PROXIES` | (empty) | Reverse proxies (CIDRs or IPs) whose `X-Forwarded-For` is believed. Empty: the header is ignored. |
| `RAMPART_SECRETS_DIR` | `/var/lib/ramparteye/secrets` | Directory of `secret.key`; must support hard links and be owned by the app user. |
| `RAMPART_SECRET_KEY` | (generated) | AES-256-GCM key as 64 hex characters; overrides the key file. |
| `RAMPART_METRICS_TOKEN` | (empty) | Bearer token of `GET /metrics`, at least 16 printable ASCII characters without spaces (for example `openssl rand -hex 32`). **Empty: the endpoint does not exist** (404). Redacted wherever the configuration is logged. See [MONITORING.md](MONITORING.md). |
| `RAMPART_DEMO` | `false` | Create the four demo accounts on the first start (set by `compose.demo.yml`). |

`GET /healthz` (no login; `200 ok` while the app and its database answer) needs no setting. The
container health checks use it.

### DefectDojo

The Settings → Integrations page is the normal way to configure DefectDojo. If
`RAMPART_DOJO_URL` is set, the connection is **managed by the environment**: every value below
comes from the environment and the form is read-only.

| Variable | Default | Meaning |
|---|---|---|
| `RAMPART_DOJO_URL` | (empty) | DefectDojo base URL; setting it switches to environment-managed mode. |
| `RAMPART_DOJO_TOKEN` | (empty) | API v2 token. |
| `RAMPART_DOJO_PRODUCT_TYPE` | `RampartEye` | Product type (created on demand). |
| `RAMPART_DOJO_PRODUCT` | `RampartEye` when empty | Product. |
| `RAMPART_DOJO_ENGAGEMENT` | `Continuous discovery` | Engagement. |
| `RAMPART_DOJO_AUTO_PUSH` | `true` | Push every completed run. |
| `RAMPART_DOJO_CLOSE_MISSING` | `false` | Close findings that are no longer seen (`close_old_findings`). |

See [DEFECTDOJO.md](DEFECTDOJO.md).

## Commands

The image's default command is `serve`. Other commands run in the app container, for example
`docker compose exec app ramparteye scan --profile Demo`.

| Command | Purpose |
|---|---|
| `serve` | Web UI, scan scheduler and DefectDojo auto-push. |
| `scan --profile NAME` / `scan <target>...` | Run a scan now. Targets given on the command line go into a profile named `CLI`. Refused without a scope. |
| `verify <expected.json> [--run ID] [--min 0.9]` | Precision/recall of a run against a lab expectation file. |
| `import <file>` | Import nmap XML or DefectDojo Generic Findings JSON as a run. |
| `export [--format csv\|json\|dojo] [--run ID]` | Export a finished run to stdout. |
| `migrate` | Apply database migrations (also done by `serve`). |
| `seed-demo <cidr> [names...]` | Add demo targets and the scan profile "Demo". |
| `audit [run]` | Safety receipt of a run as JSON; non-zero exit unless every check passed (a failed or unmeasured check, i.e. `failed` or `incomplete`). |
| `dojo push [--run ID]` | Push a run to DefectDojo now. |
| `reset-admin [--login NAME]` | New one-time password for a user (default `admin`). |
| `version` | Print the version. |

Exit codes: 0 success, 1 failure, 2 usage, configuration or scope error.

## Reverse proxy

RampartEye serves plain HTTP; for anything beyond localhost put a TLS-terminating reverse proxy in
front of it and:

- set `RAMPART_TRUSTED_PROXIES` to the proxy's address, so the login throttle sees real client
  addresses (otherwise all clients share one address and lock each other out);
- do not buffer `/events`: it is a Server-Sent Events stream for live scan progress;
- do not set a global response timeout shorter than a scan; the server itself sets no write
  timeout for the same reason.

nginx example:

```nginx
server {
    listen 443 ssl;
    server_name ramparteye.example.internal;
    # ssl_certificate ...; ssl_certificate_key ...;

    location / {
        proxy_pass http://127.0.0.1:9080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /events {
        proxy_pass http://127.0.0.1:9080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 1h;
    }
}
```

## Operating notes

- Run one `serve` per database. On start it resets chunks left running by a previous process,
  which would also reset the work of a second `serve`. The `scan` CLI may run next to `serve`; it
  does not reset `serve`'s work.
- macOS and Windows: Docker Desktop runs containers in a VM, so host networking does not reach
  your LAN. Use a Linux host for real scans; the demo works everywhere.
- Demo requirements: about 20 images, about 1.5 GiB RAM, about 3.5 minutes per scan, Docker
  Compose 2.24 or later. The lab uses `10.20.0.0/18`, which must not collide with your LAN, a VPN
  or another Docker network; one demo per Docker host. The lab network is internal (no egress).
