# Scan lab

A docker network for demonstrating and verifying RampartEye. **Scan only this network**
(`10.20.0.0/18`) or other targets you are authorised to scan.

The lab is bundled in [`compose.demo.yml`](../compose.demo.yml) (every lab file is inlined there),
so `install.sh --demo` needs nothing else. This directory holds what changes the lab between scans
and the ground truth to check a scan against:

- `variants/run{1,2,3}.yml`: compose overrides applied on top of `compose.yml` and `compose.demo.yml`.
  A service is removed with `scale: 0`; a service added only in a variant (`intranet`) is removed
  again by `--remove-orphans` when you switch back to run1.
- `change.sh`: switches the demo stack to a variant and waits until every expected service accepts
  TCP connections.
- `expected/run{1,2,3}.json`: ground truth, generated by `gen_expected.py`.

Layout:

- Network `ramparteye-lab`, `10.20.0.0/18` (16,384 addresses), gateway `10.20.0.1`.
- 30 targets on fixed addresses spread across the whole /18. The RampartEye app joins the network at
  `10.20.63.251` with `NET_RAW`/`NET_ADMIN` (SYN scan, ARP discovery) and the lab as its only scope.
- About 1.5 GiB RAM with everything running (Jenkins ~400 MiB, MySQL ~170 MiB). Images are pinned;
  one small image (alpine + openssh, socat, busybox-extras) is built locally from an inline
  Dockerfile.

## Usage

```sh
./install.sh --demo --dir /tmp/ramparteye-demo   # or, from a checkout:
docker compose -f compose.yml -f compose.demo.yml up -d   # needs RAMPART_DB_PASSWORD

lab/change.sh run2       # switch the running demo stack to run2 (also run1, run3); idempotent
lab/change.sh down       # docker compose down -v --remove-orphans
docker compose -f compose.yml -f compose.demo.yml exec app ramparteye scan --profile Demo
docker compose -f compose.yml -f compose.demo.yml exec app ramparteye verify /tmp/run2.json
python3 lab/gen_expected.py           # regenerate expected/*.json (--check: verify they are fresh)
make e2e                              # all of it: run1 -> run2 -> run3, precision/recall 1.0
```

`change.sh` uses the compose project from `COMPOSE_PROJECT_NAME` (default `ramparteye`) and the
variables from the environment or `.env`. The app container starts with `ramparteye seed-demo
10.20.0.0/18 staging.lab.local`, which creates the scan profile "Demo".

## expected/runN.json

Generated by `gen_expected.py`, the single source of truth, so edit that script and not the JSON:

```json
{"run":"run2","network":"10.20.0.0/18",
 "infra":[{"ip":"10.20.0.1","note":"docker bridge gateway"}, ...],
 "hosts":[{"ip":"10.20.0.10","name":"nginx-web","services":[
   {"port":80,"proto":"tcp","product":"nginx","version":"1.27.3","actual":"nginx 1.27.3",
    "in_top1000":true,"detections":["staging-vhost"]}]}],
 "changes_from_prev":[{"kind":"changed","ip":"10.20.40.70","port":80,"proto":"tcp","in_top1000":true,
   "old":"Apache httpd 2.4.58","new":"Apache httpd 2.4.62"}]}
```

- `product` and `version` are what `nmap -sV --version-light` reports. nmap gives PostgreSQL 16.6
  as `16.0 - 16.2` and CoreDNS as `NLnet Labs NSD`, and busybox httpd gets an empty product.
  `actual` holds the real software.
- `changes_from_prev[].kind`: `host_up`, `host_down`, `new`, `gone`, `changed`, `unstable`, the
  change kinds of RampartEye. Host-level entries use `port: 0, proto: ""`. A host that appears or
  disappears also lists each of its services as `new`/`gone`. `unstable` means at least 2 up/down
  flips within the last 5 runs.
- `infra` lists addresses that are not targets: `10.20.0.0` (the docker bridge answers ARP for the
  network address), `10.20.0.1` (gateway) and `10.20.63.251` (the app). `ramparteye verify`
  ignores them; the demo excludes them from scans (`RAMPART_SCAN_EXCLUDE`).
- Detection names map to RampartEye signature ids in `ramparteye verify` (`staging-vhost` is
  `staging-env`, `login-panel` is `login-page`, `mqtt-anonymous` is `mosquitto-mqtt`, and so on).

## Determinism notes

Change detection is checked exactly, so every fingerprint has to be the same in every scan:

- **Telnet (10.20.24.30:23)** is a socat banner, not the real busybox telnetd. The real daemon sends
  the option negotiation and the login prompt in separate writes, and nmap reported version `""`
  or `1.14.0 or later` depending on how they arrived.
- **CoreDNS (10.20.48.90:53)** has `timeouts { read 10s }`. The default 3 s TCP read timeout equals
  nmap's tcpwrapped threshold, so the port flipped between `NLnet Labs NSD` and `tcpwrapped`.
- **`change.sh` waits** until every service in `expected/<run>.json` accepts TCP connections, so a
  scan started right after a switch does not miss Jenkins, MySQL or Tomcat while they boot.
- **One lab per docker host.** The network name and subnet are fixed, so two demo stacks (for
  example `install.sh --demo` and `make e2e`) cannot run at the same time.
